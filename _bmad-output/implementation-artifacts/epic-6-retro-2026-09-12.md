# Epic 6 Retrospective: Admin-Assisted Content Sourcing

Run **out of order** — this retrospective was completed after Epic 7 (Employee Roster Management) and Epic 8 (Application Theming) had *both* already shipped in full. Part 2 of this retro is therefore reframed from forward-looking "next epic preparation" into a check of whether Epic 6's lessons actually carried into the work that followed it, since there was no next-epic planning gap to fill.

## Epic Summary

**Epic 6 — Admin-Assisted Content Sourcing:** 10/10 stories done (6.1–6.10), covering per-admin/org-wide credential storage (6.5), live content search across YouTube and Udemy (6.6), manual content link entry (6.7), review/approve/attach with days-to-complete estimation (6.8), reject-approved-content (6.9), and the Skills tab frontend shell — card grid, lookup panel, API keys modal, watch modal (6.10) — on top of the Skills module foundation, creation, edit/delete, and `ever_assigned` wiring (6.1–6.4).

**Velocity:** all 10 stories shipped across essentially two days (2026-09-09 → 2026-09-10) — the fastest epic in the project to date.

**Quality:** every story received a full 3-layer adversarial code review (Blind Hunter / Edge Case Hunter / Acceptance Auditor). Every single review found something real worth fixing — no rubber-stamp passes.

**Production incidents:** 0 (local pilot, no production target).

**Blockers encountered:** none epic-specific; the pre-existing `conftest.py` DB-pool-corruption workaround (see Lesson 1) continued to shape how tests were written.

## What Went Well

- **Pattern reuse on concurrency guards.** The `requestIdRef`/`isMountedRef` stale-response guard, first established in `DeleteSkillModal`/`ApiKeysModal` (6.3/6.5), was deliberately reused verbatim rather than reinvented in `NewSkillModal` (6.5) and `CurrentlyApprovedContent` (6.9/6.10). This is exactly the kind of convention propagation the team wants more of.
- **Test-baseline discipline stabilized.** Epic 5's close left the frontend pre-existing-failure count genuinely confused ("20" vs. a claimed "2"). By Epic 6, every story cleanly tracked and reconfirmed a stable "3 pre-existing failures" baseline, story to story — a real fix to a real Epic 5 action item.
- **"Checked box needs a covering test" discipline held.** Every finding across all 10 stories that required a code change shipped with a paired new test — no exceptions found in the story log. This closes another Epic 2 action item.
- **TalentPilot's read:** epic went smoothly overall.

## What Slowed Us Down / Challenges

- **Credential and security-adjacent work carried more edge cases than average** (TalentPilot's direct feedback). Stories 6.5 (per-admin/org-wide credential storage, Fernet encryption) and 6.6 (live search using those credentials) were the epic's most decision-heavy stories — the only two decision-needed HALTs in the epic both landed here (the `ADMIN_KEY_ENCRYPTION_SECRET` local-pilot-secret convention, and Udemy's `{client_id, client_secret}` single-column JSON packing).
- **A recurring bug class: substring-matched YouTube URLs.** Story 6.7's review caught `ContentPreviewModal.tsx` detecting YouTube via a substring regex instead of a real hostname check — a non-YouTube URL merely *containing* `youtube.com/watch?v=` (e.g., in a query parameter) would silently embed as the wrong video. The **same bug shape recurred** and had to be independently re-fixed in Story 6.8's `_extract_youtube_video_id`. Two stories, one bug pattern, two separate discoveries in review rather than one fix propagating forward.
- **A serious one: Story 6.8's metadata unit mismatch.** Admin-attached content wrote `duration_hours` (a float) while the dashboard's existing derivation path (`ProgressRepository`) reads `content_metadata.get("duration")` expecting seconds. Left unfixed, every Assignment on admin-attached Content would have been **permanently stuck "In Progress" at 0%, never "Completed"** — a direct violation of the epic's own single-derivation-authority principle (AD-3). Caught only because a code reviewer traced the actual read contract rather than trusting the AC's literal field name.
- **Reduced live-browser verification coverage.** Stories 6.5, 6.7, 6.8, and 6.9 all shipped without an interactive browser pass ("no Playwright/browser tool available this session"), relying on automated test suites instead. Epic 8's Story 8.1 later *did* get full Playwright verification — showing the tooling gap wasn't permanent, just inconsistent during Epic 6.

## Closing Notes

The standout pattern this epic: **every code review found something real**, continuing the trend first named in the Epic 1 retro. Two of Epic 6's findings (the URL-substring bug's recurrence, the metadata-unit-mismatch near-miss) were serious enough that, left unfixed, they would have silently broken working features rather than crashing loudly — reinforcing that adversarial review is earning its cost here. This retro is where that changes, per TalentPilot's explicit decision to schedule it now.
