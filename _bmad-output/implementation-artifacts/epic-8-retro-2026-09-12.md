## What Went Well

- **Direct pattern reuse kept the new code idiomatic on the first pass.** `ThemeContext.tsx` mirrors `AuthContext.tsx`'s exact Provider/hook shape — no new state-management pattern introduced.
- **Story 7.7 paid off immediately.** Because `Dashboard.tsx`/`SkillsPage.tsx`/`EmployeesPage.tsx` already delegate their header to `HrAppShell.tsx` (Story 7.7's shared-shell extraction), one toggle placement covered all three HR-side AC3 surfaces instead of three separate wiring jobs.
- **A real Tailwind v4 gotcha was caught during story creation, not after shipping.** This app runs Tailwind v4.3.2, whose dark-mode mechanism is a CSS-side `@custom-variant dark` declaration — not the v3 `darkMode: 'class'` config flag. A v3-shaped implementation would have silently only followed OS preference and never honored a manual toggle.
- **Live-verification discipline held** across a genuinely wide, 34-file mechanical change — full regression at every checkpoint, not just at the end, and a live-browser pass both before and after the code-review patches.
- **The team made real design decisions in the absence of any UX spec**, and documented them (a mechanical Tailwind-stock-scale palette-mapping table) so a 25+ file pass stayed consistent rather than re-derived per file.

## Challenges & What We Learned

- **No UX design existed for this feature at all.** The PRD's own `[NOTE FOR PM]` flagged the gap; the story had to make both the palette and toggle-placement decisions itself, anchored only to the epics AC's literal "alongside the user-menu" text.
- **A real, would-have-shipped severity-1 bug: the outermost provider had no read-path guard.** `ThemeContext.tsx`'s `getInitialTheme()`/`getSystemTheme()` called `localStorage.getItem`/`matchMedia` with no `try/catch`, unlike the already-guarded write path. Since `ThemeProvider` wraps the entire app — including `AuthProvider` and `Login` — a throw from either call (private-browsing storage restrictions, a locked-down sandbox) would have white-screened the *entire app* at first render, with no way to even reach the login page to work around it. Caught by code review, fixed to match `index.html`'s inline script's already-correct equivalent.
  - **Pattern to watch going forward:** this is the same *shape* of lesson as Story 7.6's TOCTOU finding ("check every `await`, not just the explicit branches") — a guarded write path does not imply a guarded read path. Worth a standing code-review habit: when one half of a symmetric pair (read/write, mount/unmount, encode/decode) is defensively coded, explicitly check the other half too.
- **A real contrast gap was missed by the original task list, not by execution.** `VideoPlayer.tsx` — rendered from both Content Discovery's inline video view and `AssignmentWatch.tsx`, both AC3 surfaces — was 100% hardcoded inline `color: '#666'` captions, untouched by the story's Task 7 file list because `AssignmentWatch.tsx` itself has no chrome of its own. The component it *mounts* was still fully light-styled. Fixed per explicit user decision to patch now rather than defer, since it's a real, reachable AC3/AC4 violation.
- **A recurring, now three-time project-documentation gap.** `project-context.md` had **zero entry** for Story 8.1 (creation, implementation, or review) until this retro found and backfilled it — the same class of gap already flagged for Stories 6.6–7.3, and again for Story 7.7. This is the **third occurrence**, and it happened on the very next story after the Epic 7 retro's own action item ("keep project-context.md current, spot-check at the next retro") was supposed to catch it. See Action Items — the remedy this time is a workflow gate, not another reminder.

## Project-Completion Readiness Review

Since there is no Epic 9, this section replaces the usual "next epic prep":

**Testing & quality:** Clean at every layer for Epic 8 specifically (404/404 tests, live-verified). Project-wide, the `tsc --noEmit` baseline has sat at 31 pre-existing errors since Story 6.10 with no dedicated cleanup story, and `conftest.py`'s `Base.metadata.drop_all()` DB-pool-corruption issue has now gone unresolved across Epics 3, 5, 6, and 7's retros.

**Deployment:** Out of scope by design — the architecture spine and PRD both fix this as a **local working copy only** build (Docker Compose Postgres+pgvector + uvicorn + Vite), not a production hosting target. Nothing here blocks calling the pilot "done" in the sense the PRD defines done.

**The one genuinely launch-relevant gap:** `auth/service.py::authenticate()` still only checks Story 1.4's hardcoded `_MOCK_ACCOUNTS` dict. This means Epic 7's entire credential-management feature set — Story 7.2's generated password, Story 7.6's regenerated password, all of it backed by real bcrypt hashes on the `Account` table — **cannot currently be used to log in**. This has been flagged in three separate stories' Dev Notes (7.1, 7.4, 7.6) since Epic 7, tracked as an open action item since the Epic 7 retro, and never scheduled. With the roadmap now complete, there is no future epic that will naturally force this to the surface — **user explicitly escalated it to top priority this session.**

**Technical debt inventory (unchanged, still open across the whole project):**
