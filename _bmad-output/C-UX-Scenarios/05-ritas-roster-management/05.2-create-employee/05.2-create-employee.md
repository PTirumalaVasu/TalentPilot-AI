### Content (English Only)

- Title: "New Employee"
- Required-field labels carry a `*`: "Employee ID/Code *", "Name *", "Email *"
- Duplicate notice (missing required field): "Employee ID/Code, Name, and Email are required."
- Duplicate notice (ID or email collision): "An employee with this ID or email already exists."
- Submit: "Create Employee"

---

### Interactions & Behaviors

| Object ID | Event | Action | Destination |
|-----------|-------|--------|-------------|
| `create-employee-btn-submit` | Click | Validate → Create (FR-24) | On success: modal closes, new record appears on 05.1, advances to 05.3 with the generated password. On validation failure: duplicate notice shown inline, modal stays open, no navigation. |
| `create-employee-btn-close` | Click | Cancel | Closes modal, returns to 05.1, no record created (true no-op, matching FR-1's cancel pattern) |
| Any required field | Blur/change after a failed submit | Re-validate | Duplicate notice clears once the conflicting value is corrected (implicit — validated again on next submit) |

---

### Page States

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default** | "+ New Employee" clicked | All fields empty, notice hidden | Fill fields, Submit, Close |
| **Validation error — missing required field** | Submit clicked, ID/Name/Email blank | Notice: "Employee ID/Code, Name, and Email are required." Form stays editable. | Fill in and retry |
| **Validation error — duplicate ID/Email** | Submit clicked, ID or Email matches an existing record | Notice: "An employee with this ID or email already exists." Form stays editable. | Correct and retry |
| **Success** | Submit clicked, validation passes | Modal closes; 05.1's list gains the new row/card; advances immediately to 05.3 (Password Reveal) | (hands off to 05.3) |

*(No network/loading state modeled in this mock — a real build would add a brief "Creating…" state on the submit button, matching 04.1's New Skill Panel precedent.)*

---

### Form Validation & Requirements

- Employee ID/Code: required, unique against active **and** archived records (PRD post-review correction — not active-only).
- Name, Email: required. Email unique, checked case-insensitively (matches FR-20's Skill-name dedup pattern).
- All other fields: optional, no format constraint (Phone accepts free text in this mock; a real build may add light format hinting, not a hard constraint).
- Employee ID/Code is never editable after creation (enforced on 05.1's Edit panel, not here).

---

### Accessibility Requirements

- All inputs have visible `<label>` elements (not placeholder-only for required fields).
- Duplicate notice uses text, not color alone, and is associated with the form via proximity (immediately above the submit button).
- Modal is keyboard-operable: Tab order follows visual order, Escape closes (same as Close), focus returns to "+ New Employee" on close.

---

## Content Rules

**Chore-relocation check (carried from 05.1):** Required-field count stays at exactly 3 (ID, Name, Email) — any temptation to make more fields required at build time should be weighed against the Hope/Worry tension this whole scenario is designed around.

---

## Out of Scope (this page)

- Bulk import — one Employee at a time (matches 05.1's Out of Scope, mirrors FR-20's Skill-creation limit).
- Real-time async validation (e.g., checking Email uniqueness via a live API call as Rita types) — this mock validates only on Submit; a real build may add debounced live-checking, not specified here.

---

## Design Constraints

- **Responsive:** Desktop-primary, same as 05.1.
- **Security:** No password field exists on this form — the password is system-generated on the server after submission (05.3), never entered or seen by Rita until the reveal step.
