## Overview

**Page Purpose:** See the current Employee roster and initiate adding a new hire — the roster is TalentPilot-AI's real login/identity source going forward (PRD §4.7), replacing the earlier hand-seeded demo list.

**Entry Point:** Primary Navigation — Rita clicks "Employees" in the **new left-side nav pane** (PRD FR-29). This page is what it opens to.

**User Mental State:** Rita's just been told a new hire starts Monday and needs onboarding skills assigned before their first day, but the only Employees in the system right now are the ones seeded at launch.

**Main User Goal:** Onboard a new hire into the system in about two minutes, without it becoming a second thing she has to maintain.

**Business Goal:** Secondary — Earn HR's Trust, Objective 2 (feature-complete launch); structurally enables the Primary Goal's Skill Assignment Flow, which can't target an Employee that doesn't exist in the system.

**URL/Route:** `/employees`

### Page States

#### Employee List (page-level, applies to both Table and Card view)

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default/Loaded** | Employees fetched successfully | Full Table or Card view per toggle, 15/page | Search, filter, toggle view, row/card actions, + New Employee |
| **Loading** | Page opens, list not yet returned | Skeleton rows/cards; toolbar remains interactive | Wait; nav still usable |
| **Empty (no employees at all)** | System has zero Employees (should not occur post-launch, but possible pre-seed) | List area replaced with: "No employees yet. [+ New Employee]" | New Employee |
| **Empty (no results for search/filter)** | Search or filter returns nothing | List area replaced with: "No employees match your search." | Clear search/filter |
| **Error** | List fails to load | List area replaced with: "Couldn't load employees. [Retry]" | Retry |

#### Regenerate Password Panel (modal, FR-28)

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default** | Regenerate icon clicked | Confirmation copy shown | Regenerate Password, Cancel |
| **Regenerating** | Confirm clicked | Button shows a brief inline spinner | Wait |
| **Success** | New password generated | Hands off to the one-time password-reveal state (05.3 pattern), scoped to this Employee | Copy password, Done |
| **Error** | Regenerate fails (network/API) | Modal stays open; inline error: "Couldn't regenerate — [Try again]" | Try again, Cancel |

#### Delete/Archive Confirmation (modal, FR-27)

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default — hard delete** | Delete icon clicked, Employee has zero Assignment history | Hard-delete summary copy | Remove Employee, Cancel |
| **Default — archive** | Delete icon clicked, Employee has Assignment history | Archive summary copy | Archive Employee, Cancel |
| **Processing** | Confirm clicked | Button shows a brief inline spinner | Wait |
| **Success** | Removed or archived | Modal closes; row/card removed from default view; toast confirms | (returns to Employee List) |
| **Error** | Action fails (network/API) | Modal stays open; inline error: "Couldn't complete this — [Try again]" | Try again, Cancel |

### Form Validation & Requirements

**Create/Edit fields (shared field set, FR-24/FR-26):**
- Employee ID/Code: required at creation, unique (checked against active AND archived records, per PRD post-review correction — not just active ones), immutable after creation.
- Name, Email: required. Email unique, checked case-insensitively (matches FR-20's Skill-name duplicate pattern, per PRD post-review correction).
- Phone, Experience, Technologies, Position/Job Title, Project, Manager Name, Location, Department: optional, no format constraint beyond Phone accepting common formats.
- Edit never exposes the Employee ID/Code field as editable — read-only display only.

**Regenerate Password / Delete-Archive:**
- No form fields — confirmation-only actions.

---

### Accessibility Requirements

- Status badges ("Active"/"Archived") use text + icon, never color-only (WCAG AA, matches PRD NFR-A2).
- Table and Card views are both fully keyboard-operable: Tab order follows visual order in either mode; the view toggle itself is a standard button group, operable via Tab + Enter/Space.
- All row/card action icon buttons carry `aria-label`s ("Edit {Employee name}", "Regenerate password for {Employee name}", "Delete/Archive {Employee name}") — never icon-only with no accessible name.
- Pagination controls are keyboard-operable and announce the current page to screen readers on change.
- Success/error toasts are announced to screen readers (matches PRD NFR-A4's existing toast-announcement pattern).
- Left Nav Pane's active-page link is indicated by more than color (matches the existing top-nav's active-link treatment, per FR-29's consequence).

---

### Real-Time Updates Architecture

**For POC:** No polling needed — this page is admin-triggered and synchronous (search, filter, create, edit, regenerate, delete/archive). The list refreshes on each of these actions, not via background polling.

## Content Rules

**Copy Tone:** Factual and efficient (HR-facing), matching 01.1/04.1's established tone — no encouragement copy, no color-only signaling.

**Chore-relocation design check (Trigger Map, Key Insights):** Every state on this page should be evaluated against "does this feel like a new chore Rita now owns?" — the 3-step sunshine path (05.1 → 05.2 → 05.3) is the scenario's own test of this; Edit/Regenerate/Delete-Archive should stay equally lightweight, not accumulate friction as secondary paths.

## Out of Scope (this page)

- **Updating 01.1 (Skills Dashboard) and 04.1 (Skills Tab) to the new left-pane nav shell.** This page introduces FR-29's shell for the first time; those two pages' specs still describe the old top-header nav and need their own update pass when FR-29 is actually built. Flagged here as a known follow-up, not silently assumed done.
- **Employee self-service profile editing.** This entire page is HR Admin-only (FR-14) — an Employee session can never reach it, and there is no employee-facing equivalent (Employee Profile View remains deferred, PRD §6.2).
- **Bulk import/export of Employees (CSV, etc.)** — one Employee at a time via Create, matching FR-24's "no bulk-import mechanism" scope note (mirrors FR-20's equivalent Skill-creation limit).
- **Password reset initiated by the Employee themselves** — only HR Admin can regenerate a password (FR-28); no "forgot password" flow exists for Employees in v1.

---

## Design Constraints

- **Responsive:** Desktop-primary (matches every other HR-facing page in this product).
- **Performance:** List loads under the same 2-second target as the Readiness Dashboard (PRD NFR-L1).
- **Security:** Neither Create, Edit, Regenerate, nor any other surface on this page ever redisplays a previously-generated password in plaintext after its one-time reveal (PRD FR-24/FR-28, post-review "server-side enforcement" correction).
