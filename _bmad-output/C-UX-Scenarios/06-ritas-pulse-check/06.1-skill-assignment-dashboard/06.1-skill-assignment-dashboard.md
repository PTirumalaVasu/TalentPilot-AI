# 06.1: Skill Assignment Dashboard

## Overview

**Page Purpose:** Give Rita an org-wide readiness temperature check the moment she logs in — org-wide stats, an Assignment Progress ring, and an Employee Segmentation pie chart — so she can confirm overall health or spot exactly who needs attention, without opening the full row grid first. Per the D1/D2 discussion, the page's real job is narrower than "show stats": it's to get Rita to the specific employees who need her, fast.

**Entry Point:** Direct login, or clicking `Dashboard` in the left nav from anywhere in the HR shell. This page is what `Dashboard` now opens to (PRD §4.10, superseding the prior behavior where `Dashboard` opened directly on the full row grid).

**User Mental State:** Rita logs in out of habit, start of her workday, before anyone has asked her a specific staffing question yet. Hoping things are basically fine and, if not, that she knows exactly who to look at; worried a clean-looking summary number is quietly masking real problems.

**Main User Goal:** Quickly identify which employees need attention and get to them fast.

**Business Goal:** Secondary — Earn HR's Trust, Objective 3 ("make trust legible, not just present") applied at the org-wide level, plus Objective 1 (primary source of truth) by widening adoption to general check-ins, not only specific staffing calls (UJ-1).

**URL/Route:** `/dashboard`

### Page States

#### Page-Level

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default/Loaded** | Data fetched successfully | Full page: stats, ring, pie chart all populated | Nav, click Needs Attention segment |
| **Loading** | Page opens, data not yet returned | Skeleton cards/ring/chart in place; nav/top bar remain interactive | Wait; nav still usable |
| **Empty** | Zero active Employees or zero active Assignments exist org-wide (e.g., very first day, pre-any-assignment) | Stats show zeros; ring/pie chart area replaced with: "Nothing to show yet — assign a Skill to get started. [+ New Assignment]" | Go to Skill Assignment Flow (03.1) |
| **Error** | Data fails to load (API/network) | Content area replaced with: "Couldn't load dashboard data. [Retry]" — nav/top bar remain usable | Retry |

#### `dashboard-segmentation-legend-needsattention` + popover

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default (zero flagged)** | No Employee currently Needs Attention | Segment shows "Needs Attention — 0", **not clickable**, no hint text | None |
| **Default (has flagged)** | ≥1 Employee flagged | Segment shows count + "Click to see who" hint, clickable | Click → open popover |
| **Popover Open** | Segment clicked | Popover shows each flagged Employee's name + flagged Skill, each a link | Click a name → navigate to drill-down; click outside/Escape → close |
| **Popover Closed** | Click outside, Escape, or after navigating away | Popover hidden | — |

*No separate loading/error state for the popover — its data is part of the same initial page load, not a second fetch.*

### Accessibility Requirements

- Pie chart segments and the progress ring use text + numbers, never color-only (WCAG AA, matches PRD §8 NFR and every other Status/Provenance surface in this product).
- The Needs Attention segment/button carries an `aria-label` ("Needs Attention, {N} employees, click to see who") and is keyboard-operable (Tab + Enter/Space opens the popover).
- Popover is keyboard-trap-safe: Escape closes it and returns focus to the segment button; Tab cycles through employee links inside it.
- Left Nav Pane's active-page link (`Dashboard`) is indicated by more than color, matching FR-29's existing consequence.
- Success/loading/error states are announced to screen readers (matches PRD NFR-A4's existing pattern).

---

### Real-Time Updates Architecture

**For POC:** No polling needed. This page's data loads once per page-view; no requirement exists (unlike FR-11's 30-second row-update guarantee for the row grid) for it to auto-refresh while left open. Revisit if pilot usage shows Rita keeps this tab open passively for long stretches.
