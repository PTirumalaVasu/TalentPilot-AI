## What was built, per planned section

### Section 1 — Page Structure & Shared Shell
Left nav extended to the current 4-link version (Dashboard active, `aria-current="page"`), shared top bar/user-menu markup reused verbatim from 01.1/05.1's convention. Page heading + subtitle in place.

### Section 2 — Top-line Stats Row (data-driven)
`renderDashboard()` computes Total Employees (`employees.length`), Total Skills Assigned (`assignments.length`), Total Completed (count where `computeAssignmentStatus(watchPercent) === 'Completed'`) — no hardcoded numbers remain.

### Section 3 — Assignment Progress Ring (data-driven)
Ring's `conic-gradient` stops and the Completed/In Progress/Not Started legend are both generated from the same computed counts via a shared `conicGradient()` helper. Overall % = `round(completed / total * 100)`.

### Section 4 — Employee Segmentation (data-driven, incl. On-Track threshold)
`computeEmployeeSegment()` implements the exact PRD FR-32 priority order: Needs Attention (≥1 assignment with `provenance === 'Needs Attention'`) overrides everything; else On Track requires completion rate ≥ `ON_TRACK_THRESHOLD` (0.8, named constant — PRD Open Question 20, not user-confirmed); else In Progress. Employees with zero assignments are skipped before segmentation runs, per spec — excluded from the denominator entirely, not force-counted anywhere.

### Section 5 — Needs Attention Popover (real data, disabled-when-zero)
`renderNeedsAttention()` renders two structurally different things depending on count — a plain `<span>` (count 0, no `data-object-id` button role, no hint text, no popover markup at all) vs. a real `<button>` with `aria-label`/`aria-expanded` and a populated popover (count > 0). This is the specific behavior the spec called out as needing to be "genuinely non-clickable," not just visually muted — verified by design (there is no click handler attached to the count-0 markup because it's a different element entirely, not a disabled one).

### Section 6 — Page-Level Loading / Empty / Error States (data-driven)
`loadAndRenderDashboard()` always shows Loading first (simulated 400ms latency, matching 01.1's convention of making the state observable), then resolves to Loaded, Empty (when the — possibly `?demo_state=empty`-forced — employee or assignment list is empty), or Error (simulated via `?demo_state=error`, or a real thrown exception). The URL param is documented in the work file's `migration_todos` as a testing-only convenience, not the real trigger condition.

### Section 7 — Interactions & Polish
Popover: Escape closes and returns focus to the trigger button (`closeNeedsAttentionPopover(true)`); outside-click closes without stealing focus; opening moves focus to the first popover link. Dashboard nav link carries `aria-current="page"`. Dev-mode overlay (`components/dev-mode.js`) included in the standard shared-script group.

## Demo data change (additive only — see work file for full rationale)

Added 3 employees (Alex, Taylor, Riley) and 5 assignments (`assign-007`–`assign-011`) to the shared `data/demo-data.js`. **Known, pre-existing data-model bug found, not fixed:** `assign-004` (Sam) has `status: "Needs Attention"` — using Status where the current PRD model requires Provenance (`architecture spine AD-3` already documents this exact conflation as something the original prototype got wrong). Left as-is since fixing it would change Sam's already-approved 01.1 row rendering as an unrelated side effect of this page's build. `computeEmployeeSegment()` reads `provenance` only, so this pre-existing bug does not produce a false Needs-Attention flag on this page.
